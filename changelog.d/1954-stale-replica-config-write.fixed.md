**core:** in a multi-replica deployment, a replica whose copy of a server was behind could write its stale copy over the shared configuration row. The overwrite included the L7 egress policy, so a tightened policy could revert to the older one at the next restart. Create, update and L7 policy delivery now build the new row from the recorded one, plus only the fields they change. They write with a compare-and-set on the row version. Create is insert-only and refuses a live row instead of overwriting it, and an update to a server a peer deleted no longer brings it back.
