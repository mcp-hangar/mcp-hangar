**core:** approving a quarantined discovery change while a discovery cycle was validating a newer definition of the same server no longer leaves discovery tracking the definition the approval replaced. The control plane ran the approved change while discovery tracked the old one, so when the source went back to the old definition it read as unchanged and was never applied again. An approval and a cycle on the same server now take turns: an approval that arrives mid-cycle waits for the cycle to finish and then sees what it left, so an approval bound to a `definition_digest` the cycle has since replaced is refused with the usual conflict. Approvals and cycles on different servers do not wait for each other. A cycle that finds the server's tracking changed while it validated -- by TTL expiry or by a management tenure rebuild -- now leaves it as it is instead of writing back the definition it read before.
