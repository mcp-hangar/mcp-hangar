**cli:** `mcp-hangar why` reads the event store the gateway writes for the configuration. A configuration that names no `event_store` or `persistence` has the gateway write `data/events.db` under its working directory, and `why` read the path `init` writes into its configurations instead, so it reported no store or showed another one. With no configuration file it reads `data/events.db` too. A relative path is read from the current directory, and the "no event store" message says so.
