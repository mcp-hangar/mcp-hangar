**core:** Hangar, as the client of a remote HTTP upstream, now sends the SEP-2243 `Mcp-Param-*` headers a tool declares with `x-mcp-header`, encoded by the MCP SDK: a null or absent value is omitted, and a value outside printable ASCII or with edge whitespace is sent base64-wrapped. The headers are built from the schema the upstream's last `tools/list` served the client, and that schema is judged by the same rule `hangar_call` applies: a tool with an invalid annotation, or one a `header_exposure` block withholds, is refused by the client too, before anything is sent. A mirrored header named like one the client already sends, such as a configured API-key header, is refused rather than allowed to replace it. The `http-custom-headers` client conformance scenario now passes.
