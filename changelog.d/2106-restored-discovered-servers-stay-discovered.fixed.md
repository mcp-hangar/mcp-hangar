**core:** With a durable storage backend (`persistence.backend: sqlite` or `postgresql`), a server that discovery registered no longer comes back as a static server after a restart. Before, the fleet was restored before discovery started and every restored id was treated as declared, so an authoritative source never removed the server again and "static always wins" protected a server nobody declared. A discovered server's row now records the source that registered it and the definition it reported, also when discovery replaces a changed definition. When an instance takes the management lease, that source governs the server again: an authoritative source that no longer reports it removes it one TTL later, even if it went away while the gateway was down, an additive source keeps it, and a definition that changed meanwhile is handled as a change. A discovered row written by an earlier version is attributed by the description discovery gave it ("Discovered from <source>"), taken over only by that source when it next reports the server, and given its origin then. Another source reporting the name cannot take it over. A discovered row whose source cannot be told, servers declared in the configuration file, servers created over the API or CLI, and rows written before provenance was recorded stay static. Re-pointing a discovered server over the API now also drops its recorded origin.
