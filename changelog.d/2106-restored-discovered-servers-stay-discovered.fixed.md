**core:** With a durable storage backend (`persistence.backend: sqlite` or `postgresql`), a server that discovery registered no longer comes back as a static server after a restart. Before, the fleet was restored before discovery started and every restored id was treated as declared, so an authoritative source never removed the server again and "static always wins" protected a server nobody declared. Only servers declared in the configuration file or created over the API or CLI are static now. A discovered server's row now records the source that registered it and the definition it reported, and when an instance takes the management lease its sources govern those servers again: an authoritative source that no longer reports one removes it one TTL later, even if it went away while the gateway was down, an additive source keeps it, and a definition that changed meanwhile is handled as a change. A discovered row written by an earlier version records no source: it is taken over when a source next reports it and stays until then, and a definition that changed while the gateway was down is not compared on takeover. Rows written before provenance was recorded read as API-created and stay protected.
