**core:** A refused call is logged with its bounded reason only. The `batch_call_refused` warning a gate refusal writes carried `error`, the refusal message the caller is told, which several gates fill with text they do not bound: the approver's own reason, a validator's reason, the server name the caller typed. The data-handling contract (#1276) allows a log line identifiers and bounded codes, so that field is gone; `gate`, `reason`, `error_type`, the identifiers and `elapsed_ms` are unchanged, and the caller still receives the message in the tool result. A gate that broke rather than refused still logs `batch_call_failed` at debug with its error (#1581).
