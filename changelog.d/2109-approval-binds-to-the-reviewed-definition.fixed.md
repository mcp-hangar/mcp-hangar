**core:** A discovery approval can now be bound to the definition the operator reviewed. `hangar_approve` takes an optional `fingerprint`, and `POST /api/discovery/approve/{name}` reads one from the query string or a JSON body; `hangar_discovered`, `hangar_quarantine`, `GET /api/discovery/pending` and `GET /api/discovery/quarantined` list it. Given, the approval applies only a definition that still has it, and otherwise is refused with `DiscoveredDefinitionChangedError` (409 on REST) naming the current fingerprint, changing nothing. An approval without a fingerprint applies whatever waits under the name, as before, and logs `discovery_approval_not_bound` at WARNING. A pending change whose source went back to the running definition, or stopped reporting it, is cleared, and so is a quarantined change whose source went back and whatever a removed source left waiting, so none of them can be approved any more. An approval now runs the input validator on the command and the source's own policy, as an automatic registration does, and a definition that fails them is refused and stays where it waited.
