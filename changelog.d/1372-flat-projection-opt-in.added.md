**core:** a front door (`tool_access.mode: front_door`) now projects only the upstream tools each server and group names in a new `tool_projection.flat` list, instead of every tool. The list is the tools served under their own names in `tools/list`, `tools/call`, `server/discover` and the `list_changed` notifications; it only narrows what policy, withdrawals and pins already allow, and prompts, resources and subscriptions do not read it. A front door with a server or group that has no `flat` key refuses to start, and a reload that drops one is refused and changes nothing. `flat` takes tool names only: `flat: all` and any wildcard are refused, a name the scope's own `tools:` does not make visible is refused naming both, and the key under `egress` is refused as contradictory (ADR-027). A server registered over REST or by discovery declares no list, so a front door projects none of its tools. `mcp-hangar init` writes the list from the tools its smoke test saw.
