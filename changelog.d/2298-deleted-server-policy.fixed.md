**core:** a server deleted over REST or unloaded with `hangar_unload` no longer leaves its tool-access policy to the next server created under the same id. The REST delete cleared the policy neither from memory nor from the store, so a server created again was governed by it at once; `hangar_unload` cleared it from memory and left the stored row, which the next restart applied again. Both now remove the policy from memory and delete the stored row, as a reload already does (#2234). A server that discovery removes keeps its policy, so an operator's deny list survives the server dropping out of discovery and back. On a gateway whose policy store replicas may share (PostgreSQL, or a coordinated fleet) the stored rows are kept, because a replica whose file still declares the server replays them.
