**core:** a replica on a release from before the peer-key name record (2.31.0 or older) can no longer rewrite a key-pinned server's row as a plain one. Its create under the name of a key-pinned server, sent to it during a rolling upgrade, replaced the row with one without `tls` and served the name unpinned. Both storage backends now install a database trigger that refuses a live configuration row under a recorded name unless it carries the recorded `key_ref`, which binds a release that never reads the record. The trigger is installed when a replica of this release first starts.
