**core:** the fleet snapshot keeps a server's `tls` block, so a server with `tls.peer_identity` (ADR-030) keeps its key list when it is rebuilt after a restart or on a peer replica, instead of returning as a plain server. Such a server's stored row has the mode `remote-peer-key`. This release reads that back as `remote`. A release that does not know the mode declines the row instead of serving the server without checking its key. A `remote-peer-key` row with a missing or malformed peer identity is refused and skipped at recovery.
