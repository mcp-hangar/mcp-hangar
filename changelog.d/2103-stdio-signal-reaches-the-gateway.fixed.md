**core:** A stdio `serve` no longer ignores a SIGTERM or SIGINT now and then. On Linux a signal sent to the process can be taken by any of its threads; when one other than the main thread took it, the gateway's main thread stayed asleep waiting for input and never ran its shutdown, so the gateway kept running until stdin closed or a SIGKILL. Over stdio the gateway now registers a signal wakeup fd that a thread of its own reads. When the main thread has not started the shutdown within 0.25 s of the signal, that thread logs `shutdown_signal_forwarded` and sends the signal on to the main thread, which then shuts down as before. Should that not reach it either, the thread logs `shutdown_signal_received` with `via=wakeup_fd`, shuts down itself, and ends the process about two seconds later. `serve --http` is unchanged.
