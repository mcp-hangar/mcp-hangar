A built-in `kubernetes-operator` role holds exactly what the Kubernetes operator calls: `mcp_servers:read`, `mcp_servers:write`, `mcp_servers:lifecycle`, `policy:read` and `policy:write`. Before this the only built-in role that could register a server and deliver egress policy was `admin`. The role holds no tool invocation, groups, discovery approval, config reload or admin permission, and its set is pinned by a test. Lifecycle is not scoped per server, so the role can start a server it did not register.
