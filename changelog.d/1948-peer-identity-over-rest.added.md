**core:** a remote server's peer identity and endpoint can be set over REST (ADR-030 §4). `POST /mcp_servers` accepts a `tls` block, and a key-pinned server may be created without an endpoint. `PUT /mcp_servers/{id}` accepts `tls` and `endpoint`; an explicit `null` endpoint clears it. Changing either on a key-pinned server, or giving a server a peer identity, needs `mcp_servers:peer_identity`. A discovered server given a peer identity becomes a human-registered one, held to the SSRF policy. An endpoint change resets the server's start backoff and failure count. One update may add or remove keys, but not replace the whole list under the same `key_ref`. Changing `key_ref` or removing a peer identity is refused, and so is a change to a server the configuration file declares. A key-pinned server cannot join a group. `GET /system` lists `capabilities: ["peer_identity"]` for the operator to check.
