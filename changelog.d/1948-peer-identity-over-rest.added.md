**core:** a remote server's peer identity and endpoint can be set over REST (ADR-030 §4). `POST /mcp_servers` accepts a `tls` block, and a key-pinned server may be created without an endpoint. `PUT /mcp_servers/{id}` accepts `tls` and `endpoint`; an explicit `null` endpoint clears it. Over the API, `tls` holds only `peer_identity` and `max_connection_age`. `verify_ssl`, `ca_cert_path` and any other key are refused with 422 and stay with the configuration file. Changing the endpoint or `tls` of a key-pinned server, or giving a server a peer identity, needs `mcp_servers:peer_identity`. A discovered server given a peer identity becomes a human-registered one, held to the SSRF policy. An endpoint change resets the server's start backoff and failure count. One update may add or remove keys, but not replace the whole list under the same `key_ref`. The following are refused: changing `key_ref`, removing a peer identity, changing a server the configuration file declares, and changing the endpoint of a server without a peer identity, which would reach only one replica (#1955). A key-pinned server cannot join a group. `GET /system` lists `capabilities: ["peer_identity"]` for the operator to check.
