**core:** a key-pinned server's `key_ref` can be changed with `PUT /mcp_servers/{id}`, and a deleted key-pinned server's name can be forgotten with `DELETE /mcp_servers/{id}/peer_identity` (ADR-030 §7, §9). Both need `mcp_servers:peer_identity`. A new `key_ref` moves the name's entry in the peer-key name record within the row's transaction. It starts a new lineage, so the key list need not share a key with the old one, and the server's digest pins must be recorded again. A `key_ref` another server holds is still refused. Forgetting a name is refused while the server is registered on any replica; once forgotten, the name can be registered without a peer identity. A configuration row written for a server the configuration file declares, by a description or L7 policy change, no longer claims an entry in the record, whose entries for that server come from the file.
