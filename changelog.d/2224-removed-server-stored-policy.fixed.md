**core:** a server created again after a restart no longer inherits the tool-access policy of the server a reload removed under the same id. The reload cleared the removed server's policies from memory and left the rows the REST endpoint had stored for it, so the next restart, and the next reload, applied them again. A reload now deletes those rows as well. On a gateway whose policy store replicas may share (PostgreSQL, or a coordinated fleet) the rows are kept, because a replica whose file still declares the server replays them on its own restart.
