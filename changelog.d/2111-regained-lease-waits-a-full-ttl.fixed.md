**core:** In a multi-replica deployment, a replica that held the management lease, lost it and later took it back no longer removes discovered servers before its first discovery cycle. It kept the last sightings from its earlier tenure, which ran out while it followed, so its first expiry check could deregister servers its sources still reported. When an instance takes the lease back it now rebuilds discovery tracking from the fleet as it is then: every discovered server is seen at that moment, an authoritative source removes one it no longer reports a full TTL after the lease was taken, a server a peer removed meanwhile is registered again when its source reports it, and a server re-pointed over the API or CLI meanwhile is no longer governed by discovery. A standalone gateway is unchanged.
