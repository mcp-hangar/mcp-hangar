**core:** a span Hangar does not create no longer carries text in its status description. The MCP SDK's SERVER span copied a JSON-RPC error's message into the status, so a front-door call of a made-up tool name exported `Tool '<name>' not found` with the caller's text in it. The telemetry data contract allows only the span's `error.type` there. The provider Hangar builds now keeps a status description only when it is `error.type`, and cuts a span name to the span attribute length limit (256 by default), whichever library started the span. The caller still receives the error message in full. A provider registered by someone else is left as its owner configured it.
