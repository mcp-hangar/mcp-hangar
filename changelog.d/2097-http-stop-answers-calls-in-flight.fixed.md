**core:** a stopping `serve --http` answers the MCP calls in flight instead of cutting their streams. On SIGTERM sse-starlette closed the stream a pending `tools/call` was answered on, so the client got `peer closed connection` while the call ran on to completion upstream (a retrying client ran it twice), and the process lived as long as its slowest call whatever `http.graceful_shutdown_timeout_s` said. The stop now waits for the MCP requests and batches in flight before it lets the streams close. With the bound unset it waits as long as they take, as before, and the response is delivered. With a bound, once it runs out each batch still running is abandoned: its caller gets a JSON-RPC error with code `-32000` and `data.reason: "shutdown"` on the same stream, the upstream servers are stopped, and the process exits within about the bound plus the component shutdown, logging `http_shutdown_abandoned_calls`. Stdio is unchanged.
