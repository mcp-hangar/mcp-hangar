**core:** a secret containing a literal `${...}` no longer fails the boot. Moving `${VAR}` interpolation out to the whole document left the original call inside `mcp_servers.<id>.auth` where it was, so that one block was interpolated twice. The second pass reads the output of the first, which makes it not a no-op: a generated password like `R9${x}q!` arrived correctly from the environment and was then read as another reference, refusing startup with `Required environment variable '${x}' is not set` -- or, if `x` happened to be set, substituting again and configuring the upstream with a credential nobody wrote. The document is interpolated once as it is read, and what comes out is a value rather than more configuration. `UPGRADE.md` now also names the consequence that moved with it: an unset `${VAR}` with no `:-default` has always been fail-closed and now fails the whole boot, not only the `auth` sub-block
