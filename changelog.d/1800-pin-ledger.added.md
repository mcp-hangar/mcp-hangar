Pins now have a history in the event log. Each time a configuration is applied, at boot and on reload, the pins it declares are compared with the server's `pin_ledger:<server>` stream and the differences are appended: `ToolPinRecorded` for a pin that is new or whose digest or upstream binding changed (naming the digest it replaced, the upstream binding, and the structure and description digests when the tool is being served as the pin is recorded) and `ToolPinRevoked` for a pin the file no longer declares. An unchanged pin appends nothing, so a restart does not repeat the history, and a second replica reads the same state from the store. `mcp-hangar why --tool NAME` prints a tool's pin history from the log alone, read-only. The approver is recorded as `config`: the configuration file carries no author.
