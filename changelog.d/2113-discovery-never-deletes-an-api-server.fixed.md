**core:** Discovery no longer deletes a server an operator took over. A discovered server re-pointed over the API (`PUT /api/mcp_servers/{id}` with a new `endpoint`), or deleted and created again over the API under the same name, carries HUMAN provenance; discovery still tracked the name, and when its source stopped reporting it, the TTL ran out and discovery deleted the operator's server. A deletion discovery starts is now refused for a server it did not register, logged once as `discovery_deregistration_refused_not_discovered` at INFO, and discovery stops tracking the name. A deletion over the API works as before, including of a discovered server.
