**ci:** changelog entries are written as one file per PR in `changelog.d/` instead of a line in a shared `## [Unreleased]` block, and `CHANGELOG.md` is assembled from them at release time. The old convention made every open PR write to the same anchor in the same file, so two PRs open at once conflicted by construction and the second to merge got a hand-resolve; release-please separately generated its own section above that block, which left the prose orphaned under the wrong heading -- v2.3.0 shipped after consolidating three of them by hand. release-please now runs with `skip-changelog: true` and keeps the version, the tag and the release PR; the fragments own the prose. Nothing about a released changelog changes for a reader: the assembled section carries the same headings, the same entries and the same PR links, and the historical file was normalized to that one format in the same pass
