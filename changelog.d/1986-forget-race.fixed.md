**core:** forgetting a deleted key-pinned server's name (`DELETE /api/mcp_servers/{id}/peer_identity`) at the same moment another replica re-created it with its `key_ref` could leave a live key-pinned server with no entry in the peer-key name record, after which a later delete and a plain re-create needed only `mcp_servers:write`. The forget now deletes the entry before it looks for a live row, and a claim holds the entries it read `FOR SHARE` until its row is written, so one of the two waits for the other.
