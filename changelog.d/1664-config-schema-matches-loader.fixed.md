`mcp-hangar config check` and `HANGAR_CONFIG_STRICT=1` no longer refuse keys the loader reads: `mcp_servers.<id>.network_mode` and `user`, `discovery.lifecycle`, and the settings block of the approval channel the config selects (`approvals.<channel>`). A test now reads the loader's source and fails when it reads a key the schema does not know, or the schema accepts one nothing reads.
