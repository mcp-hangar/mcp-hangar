**core:** A trace now shows what happened to a call's payload on the way through. Request and response mutation each add a `hangar.shaping.mutation` event to `batch.call.<tool>`, with the direction, whether a mutator changed the payload and how long it took. A result dropped by the per-call size limit adds `hangar.shaping.drop`, with its size and the limit. Batch truncation runs in its own `batch.truncate` span, which counts the results it cut and says whether it stored a continuation. Only timing, sizes, counts and flags are recorded, never a payload or a continuation id, and the default empty mutator pipeline records nothing.
