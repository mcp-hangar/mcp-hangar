Digest pins can be bound to the upstream they were taken from. `mcp-hangar pin --write` now writes `tool_projection.upstream` beside the pins: an identity derived from the upstream (the origin of a remote endpoint, the image of a container, or the executable and a hash of the command line of a subprocess; never the server id and never any secret). A server whose upstream differs does not match the pins, whatever its tools say, so a pin block copied to another server, or a renamed server pointed at a different upstream, is refused under `block` (reported under `warn` and `audit`), the mismatch event naming `expected_upstream` and `observed_upstream`, and `pin --check` reports it as drift of `(upstream)`. Pins written without `upstream` check the definition only, as before.
