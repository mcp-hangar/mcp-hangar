`hangar_call(max_attempts=1)` now means exactly one attempt when the gateway configures a `retry:` policy. It was read as "unset", so the default and an explicit 1 both got the configured count (3) and a caller could only lower it to 2, which left no way to call a tool that is not idempotent once. `max_attempts` now defaults to `null` (use the configured policy, or a single attempt when none is configured); a larger number still only lowers the configured count.
