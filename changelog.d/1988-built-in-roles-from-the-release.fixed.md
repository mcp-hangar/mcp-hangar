**core:** on a shared auth store, the built-in roles in force no longer depend on which replica started last. Each replica seeded its own release's built-in roles over the stored ones at startup and authorized from the stored ones, so a 2.31.0 replica took `mcp_servers:peer_identity` away from `kubernetes-operator` on every 2.32.0 replica, and an older replica would give back a permission a later release removed. A built-in role is now enforced as the running release defines it, and a custom role can no longer take a built-in name.
