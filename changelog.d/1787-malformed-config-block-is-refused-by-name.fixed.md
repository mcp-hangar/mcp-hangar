A configuration block of the wrong kind (a string where a mapping goes, a number for a mode, a list of numbers for group members) is refused as a `ConfigurationError` naming the server or group, `Invalid configuration for 's0': AttributeError: ...`. It reached the loader's own reads and ended boot or a reload in a bare `AttributeError`, `TypeError` or `ValueError` traceback that named nothing; the new config fuzz target found it in about one spec in six. A group member's unknown mode is now reported the same way, a `ConfigurationError` that names the group.
