**core:** every path that brings a server into the fleet without writing a configuration row now checks the peer-key name record (ADR-030 §9). Loading or reloading the configuration file refuses a file in three cases: it declares a recorded name without its recorded `key_ref`, it declares a recorded `key_ref` under another name, or it gives two of its servers the same `key_ref`. Recovery does not restore a row under a recorded name that lacks the recorded peer identity. `hangar_load` refuses a recorded name. Discovery does not register a recorded name and logs it as `discovered_peer_key_upstream`, and its repeated attempt to delete a server moved to a key-pinned registration is logged at info.
